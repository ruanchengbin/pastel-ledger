# 后端测试计划 · Pastel Ledger Server

> 测试对象：`005.后端代码`  
> 启动方式：`npm start`（或 `node --watch src/server.js` 开发模式），监听 `http://localhost:3000`  
> 数据库：MySQL 8.0.34，schema `pastel_ledger`  
> 现有基建：`smoke.mjs`（Node fetch，覆盖健康检查 + Auth + Account + Transaction + Category + Budget + Stats + Sync + Export + Theme，36 个关键断言），`e2e-auth.mjs`（Auth 链路），`src/validators/schemas.js`（Zod 参数校验）

---

## 1. 技术栈与目录结构

| 层 | 技术 |
|---|---|
| 运行时 | Node.js ≥ 18（CommonJS） |
| Web 框架 | Express 4.19 |
| DB | mysql2 3.9（连接池） |
| 鉴权 | JWT（access + refresh） |
| 密码 | bcryptjs 2.4 |
| 参数校验 | Zod 3.23 |
| 安全 | helmet、express-rate-limit、cors、dotenv |
| 邮件 | nodemailer（可选，开发环境验证码打印控制台） |
| 现有测试 | `smoke.mjs`（集成级，HTTP 层）、`e2e-auth.mjs` |

目录结构：
```
src/
  app.js              # Express 装配，挂载全部路由 + 中间件
  server.js           # entry：自动建表、监听、优雅关闭
  db/pool.js          # mysql2 连接池（max=10, queueTimeout=30s）
  config/index.js     # dotenv 配置读取
  middleware/
    auth.js           # JWT 解析 + 用户注入 req.user
    error.js          # 全局错误处理（Zod / DB / 业务错误码映射）
    rateLimit.js      # 不同路由组不同速率
  routes/*.js         # 10 个路由组（auth/transaction/category/budget/stats/sync/export/account/link）
  controllers/*.js    # 薄控制器，只做参数取参/返回格式化
  services/*.js       # 业务逻辑（9 个 service）
  utils/              # bcrypt / jwt / error / response / centYuan / mailer / crypto
  validators/schemas.js  # Zod schema 定义
```

## 2. 核心业务模块

| 模块 | 路由前缀 | 关键端点 | 业务说明 |
|---|---|---|---|
| 鉴权 | `/auth` | POST login / register / refresh / forgot / reset | bcrypt 密码 + JWT 双令牌 |
| 账户 | `/account` | GET me / PUT name / PUT theme / PUT password / DELETE | 主题、昵称、密码、注销 |
| 流水 | `/transactions` | CRUD + undo-restore | 金额以「分」存储，软删除 30 秒可恢复 |
| 分类 | `/categories` | CRUD + PUT order | 按支出/收入分组，自定义排序 |
| 预算 | `/budgets` | GET / PUT / GET progress | 周期总额 + 分类子预算，实时进度 |
| 统计 | `/stats` | summary / breakdown / trend / comparison | 汇总、构成、6 月趋势、同比 |
| 同步 | `/sync` | GET full / GET pull / POST push | 移动端全量/增量同步，支持 `?include_partners=1` 合并关联账户流水 |
| 导出 | `/export` | GET json / GET csv | 全量账本导出，**不走 {code,data} 包裹**（直接文件流） |
| 关联 | `/links` | GET list / POST request / POST accept/reject/cancel/revoke | 跨账户项目的状态机 |

## 3. 高风险功能

### P0 风险

| # | 风险 | 位置 | 原因 | 建议测试手段 |
|---|---|---|---|---|
| R1 | **跨账户权限越权** | `transactionService.resolveAccountScope` / `linkService.resolveVisibleAccounts` | account_ids 过滤时 caller 只能查自己的 visibleAccounts，若 JOIN 写漏条件可被遍历 | 构造 account_ids=[其他用户 id] 试 403；并发请求同一 link.accept 观察状态不变 |
| R2 | **sync/full include_partners 合并** | `syncService.full()` | JOIN categories + users 取 partner 侧分类兜底字段，SQL 拼错会丢自己分类或带错 readonly 标记 | 单测级校验：自己 tx readonly=false + partner tx readonly=true + owner_email 非空 |
| R3 | **link 状态机死锁** | `linkService.update()` | 同一 pair 双向并发 accept / revoke，状态转换表是否幂等 | 压测 10 并发同时 accept 同一条，期望只有一条成功或两者都 accepted |
| R4 | **undo/restore 窗口** | `transactionService.softDelete` | 30 秒内 restore 可用，过期后 hard delete；并发 delete+restore 是否稳定 | 时间控制：delete 后 0 秒、29 秒、31 秒分别 restore |
| R5 | **金额分/元边界** | 全局 `utils/centYuan.js` + `validators/schemas.js` | `amount_yuan → 分` 的舍入、`0.005` 边界、负数金额 | 边界：0、0.005、1.005、99999999.99 |

### P1 风险

| # | 风险 | 位置 | 原因 |
|---|---|---|---|
| R6 | **JWT 刷新旋转** | `authService.refresh()` | 旧 refresh_token 是否加入黑名单；连续两次 refresh 是否第二次失败 |
| R7 | **主题列自动补列** | `accountService.ensureSchema()` | ALTER TABLE ADD COLUMN IF NOT EXISTS 在 MySQL 8.0 不同 patch 行为；并发启动多实例时 |
| R8 | **nodemailer 降级** | `mailer.js` | SMTP 不可用时打印验证码到控制台，生产环境不能漏发 |
| R9 | **export 不走标准响应包裹** | `exportController` | smoke 脚本已识别此特殊契约，但前端/小程序端解析逻辑不能按 {code,data} 读 |

### 4.1 L1 接口级详细用例（基于 smoke.mjs 补强）

**补充 link 状态机矩阵**（现有 smoke 未覆盖）：

| 场景 | 步骤 | 预期 |
|---|---|---|
| 双向同时发起 → 自动互 accepted | demo POST /links(partner) + partner POST /links(demo) | 两条都 status=accepted，无 pending 残留 |
| 对方已 pending 时再发 → 自动 accepted | demo POST /links(partner) → partner 再发 /links(demo) | partner 那条 accepted，demo 那条不变 |
| cancel 仅 requester | demo 请求 pending → demo cancel | cancelled |
| accept 仅 target | demo 请求 pending → demo accept | 400 InvalidState（或 403） |
| revoke 双方均可 | accepted → requester revoke 或 target revoke | revoked |
| 接受不存在的 link id | POST /links/{uuid}/accept | 404 / code=40410 |
| 接受自己（邮箱=自己邮箱） | POST /links(自己邮箱) | 422 / code=42210 |

**补充 include_partners 返回验证**：

| 断言 | 条件 |
|---|---|
| `visible_accounts.length >= 2` | 已关联 |
| 属于 demo 的 tx `owner_email` 为 null 或 demo.email | 自己的 |
| 属于 partner 的 tx `owner_email = partner.email`（小写） | 对方的 |
| partner tx `readonly = true` | 只读 |
| partner tx 含 `category_name / icon / color` | 兜底分类字段 |

### 4.2 L2 集成链路用例

**场景 A：完整账本生命周期**
1. 注册 demo → 登录 → 拉 /sync/full（空）
2. 创建 5 笔 expense（不同分类）+ 2 笔 income
3. 创建 1 自定义分类 → 创建预算 → 检查 /budgets/progress
4. 查看 /stats/summary → 手工核对总额 ≈ 6 笔金额
5. 删除 1 笔 → undo（30s 内 restore）
6. /export/json 检查导出数据含刚删除又恢复的那笔

**场景 B：跨账户关联链路**
1. 注册 partner
2. demo POST /links → partner GET /links 看到 pending
3. partner POST /links/demo → 两条自动 accepted
4. demo GET /sync/full?include_partners=1 → visible_accounts 包含 partner
5. demo 在流水页看到 partner 的 tx（只读）
6. demo /links revoke → 再次 sync 只剩自己

**场景 C：切换账号**
1. demo 登录 → 改主题 ocean → 退出
2. partner 登录 → 改主题 mint → 退出
3. demo 重新登录 → 立即 PUT /account/theme? 拉回来 → 检查 theme=ocean（不是 mint）

### 4.3 L3 边界用例

| 类别 | 输入 | 期望 |
|---|---|---|
| amount | 0 | 允许（或根据 PRD） |
| amount | -1 | Zod 拒绝 |
| amount | 99999999.99 | 允许（边界） |
| email | `'' / 'bad' / 'a@b'` | Zod 拒绝 |
| category_id | 不存在的 uuid | 外键错误 / 400 |
| 并发 delete+restore | 10 次并发 | 幂等，只成功 1 次 |

### 4.4 L4 性能（可选，有 loadtest 工具时）

| 指标 | 目标 |
|---|---|
| /sync/full 1000 tx | < 300ms |
| /stats/trend 6 个月 | < 150ms |
| 连接池耗尽 | 不 crash，等待 30s 内返回 |
